这是博客的第一份「日摘」：用表格回顾当天实际做了什么，而不是用脚本从正文里剪几句充数。

任务

项内容结果
建站本地静态博客：首页、侧栏、文章列表完成
内容结构发布时间、标签、文末 AI 提炼（写在文头元数据）完成
约定文件命名、config.toml、标签清单完成
写作入口本机网页编辑器（不暴露公网）完成
分类标签页与标签归档完成
版本管理安装 Git 并 git init完成初始化；尚未推远程
上线GitHub Pages 工作流文件已准备，等远程仓库
假提炼浏览器里截断拼接「生成草稿」已删除

进展

进展说明
源码与产物分离文章在 posts/，网页在 site/，构建可重复
命名统一文章改为 YYYY-MM-DD-...md
编辑体验可在浏览器新建/编辑，保存后自动构建
日摘体例本日这份日志即样例：表格 + 日摘 标签

问题

问题影响处理
本机一度没有可用 Python / Git构建与版本管理卡住手动安装后恢复
Git 用包管理器下载失败无法自动装 Git改手动安装
编辑器旧进程占着旧端口改了代码页面仍像没更新换端口并重启进程
截断脚本充当「AI」摘要质量明显差一截去掉按钮，改走真模型写日摘

反思

点结论
便宜步骤 vs 贵步骤生成 HTML 可以全本地、每次全量构建；归纳、提炼必须由模型在对话或定时助手里做
公网写作本机编辑已经满足日常；外网可写要登录和服务器，先不做
日摘位置不要塞进每篇文章的提炼框；单独发一篇日志，标签用 日摘

无实质进展的日子可以不发，或只写一行「无记录」。

AI 提炼

结构化摘要 · 便于回顾

一句话今天把试验博客做成能读、能分类、能在本机网页里写；高质量摘要必须由模型写，不能靠截断脚本假装。
要点
  • 静态站骨架与约定已落地
  • 本机编辑器可用，公网保持只读
  • 日摘应作为独立日志发布，而不是污染每篇文章的提炼框
